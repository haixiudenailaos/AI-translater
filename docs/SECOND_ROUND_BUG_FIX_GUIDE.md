# 第二轮 Bug 修复指南

本文档记录第一轮 Bug 修复完成后再次审查发现的问题。审查基于 2026-07-15 的当前工作区，重点检查：

- EPUB 导入、旧译文恢复和导出的一致性。

本文档不替代 `BUG_FIX_GUIDE.md`。第一轮文档记录原始缺陷，本文件记录修复实现后的回归、边界缺口和新发现。

## 3. R2-BUG-001：正确解析 ebooklib spine ID

### 位置

- `src/core/epub_processor.py:59-106`

### 现状与触发方式

ebooklib 常见的 `book.spine` 条目为：

```python
("chapter_1", "yes")
```

当前代码取得字符串 `chapter_1` 后，只处理带 `idref` 属性的对象或已经是文档对象的值。字符串不会调用 `book.get_item_with_id()`，最终 `doc_item` 为 `None` 并被跳过。

### 修复要求

- `itemref` 为字符串时调用 `book.get_item_with_id(itemref)`。
- 兼容字符串、带 `idref` 的对象和文档对象三种形态。
- 明确处理 `linear="no"` 的策略，不要读取后完全忽略 `linear`。
- 当 spine 非空但没有解析出任何正文时，导入必须失败，不能生成“成功但空内容”的映射。

### 验收标准

- 最小 EPUB 的字符串 spine 能按阅读顺序产生正文。
- 对象 spine 和字符串 spine 得到完全相同的章节列表。
- 无法解析全部 spine 时抛出明确异常。
- 导入和导出共用同一组 spine fixture 测试。

## 4. R2-BUG-002：密钥迁移必须确认持久化成功

### 位置

- `src/utils/secure_storage.py:23-76`
- `src/config/config_manager.py:111-143`
- `src/config/config_manager.py:145-162`
- `src/config/config_manager.py:377-417`

### 现状与触发方式

`store_key()` 在系统密钥环不可用或写入失败时，将 Key 放入当前进程环境变量并返回 `True`。配置迁移随后仍会删除 JSON 中的明文 Key。进程退出后环境变量消失，下次启动无法恢复 Key。

密钥环后端检测也通过 `type(backend).__name__` 判断 `"fail.Keyring"`，但 `__name__` 通常只是 `"Keyring"`，可能把失败后端误判为可用。

### 修复要求

- 区分 `PERSISTED`、`SESSION_ONLY` 和 `FAILED`，不要只返回布尔值。
- 只有持久化写入成功并回读一致后，才能删除旧明文字段或旧文件。
- 会话级环境变量降级必须明确提示用户“重启后失效”，不能显示普通保存成功。
- 使用 keyring 后端的真实优先级或模块类型判断可用性。
- 迁移失败时保留旧配置，且不得在日志中写入 Key。

### 验收标准

- 模拟无 keyring、失败后端和拒绝写入时，旧 JSON Key 仍然存在。
- 密钥环写入成功但回读不一致时不删除旧 Key。
- 正常密钥环迁移后重启仍能读取相同 Key。
- 空 Key 删除失败时向 UI 报告失败，而不是保留旧 Key 后显示成功。

## 5. R2-BUG-003：预设迁移不能重新写回明文 Key

### 位置

- `src/config/config_manager.py:323-345`

### 现状

加载旧预设时，代码先 `pop("api_key")` 并存入密钥环，随后又执行：

```python
data["api_key"] = get_key(...)
```

当 `needs_rewrite` 为真时，包含运行时 `api_key` 的 `presets` 对象会整体写回 JSON，导致明文 Key 再次落盘。

### 修复要求

- 持久化对象和返回给 UI 的运行时对象必须分离。
- 写回磁盘前重新构造只包含非敏感字段的对象。
- 密钥迁移持久化成功后才能移除旧字段。

### 验收标准

- 迁移旧预设后磁盘 JSON 中不存在 `api_key`。
- 返回给 UI 的预设仍能临时包含运行时 Key。
- 搜索配置目录和日志找不到完整测试 Key。

## 6. R2-BUG-004：禁止按位置复用已变化原文的译文

### 位置

- `src/core/epub_processor.py:342-374`
- `src/core/epub_processor.py:409-430`

### 现状

带校验和的 locator 未命中后，代码直接按 `chapter_id + block_index` 复用旧译文，没有比较原文或校验和。同一位置的原文发生修改时会静默挂上旧译文。

### 修复要求

- 位置降级匹配必须同时校验规范化原文或完整校验和。
- 原文发生变化时保留为空，并记录可定位的迁移警告。
- 不要用 8 位 MD5 作为跨版本数据唯一性保证；至少保存完整强校验和。

### 验收标准

- 修改同一段原文后不会自动复用旧译文。
- 只移动位置但原文完全相同的段落可按明确规则恢复。
- 重复原文无法唯一定位时不自动选择任意一条译文。

## 7. R2-BUG-005：章节 ID 必须保留唯一路径

### 位置

- `src/core/epub_processor.py:112-150`

### 现状

非 `Text/` 路径最终只保留文件名。例如：

```text
part1/chapter.xhtml -> Text/chapter.xhtml
part2/chapter.xhtml -> Text/chapter.xhtml
```

两个章节的 locator 和序号索引会互相覆盖。

### 修复要求

- 以 OPF 根目录为基准保存规范化的完整相对路径。
- 只移除容器根前缀，不删除实际章节目录。
- 检测到规范化 ID 冲突时直接拒绝生成映射。

### 验收标准

- 不同目录下的同名章节拥有不同 ID。
- Windows 和 POSIX 分隔符归一化后得到相同 ID。
- reimport 和 export 使用完全相同的章节 ID 规则。

## 8. R2-BUG-006：导出前验证源 EPUB 指纹

### 位置

- `src/core/epub_processor.py:542-549`
- `src/core/epub_processor.py:770-778`
- `src/core/epub_processor.py:910-973`

### 现状

映射中保存了源文件大小和修改时间，但导出时没有验证。若原路径上的 EPUB 被替换或修改，代码仍按全局位置把旧译文写入新结构，新增或删除一个段落就可能导致后续译文整体错位。

### 修复要求

- 导入时保存内容哈希、大小、mtime 和必要的章节结构摘要。
- 导出前至少验证内容哈希；不一致时中止并要求重新关联或迁移。
- 替换文本时使用稳定 locator，而不是仅使用全局计数器。

### 验收标准

- 修改源 EPUB 后旧映射不能直接导出。
- 仅文件时间变化但内容不变时可安全继续。
- 增删一个段落不会把后续译文写入错误位置。

## 9. R2-BUG-007：保留 EPUB 内联格式

### 位置

- `src/core/epub_processor.py:958-972`

### 现状

导出替换段落时会删除节点下所有文本节点，再在块节点开头插入一个纯文本译文。`em`、`strong`、`a`、`ruby`、`span` 等标签虽然可能保留为空标签，但其内容和语义已经丢失。

### 修复要求

- 明确定义翻译单元与 DOM 文本节点的映射策略。
- 无法可靠保留内联结构时，不得宣称“保留原结构与样式”。
- 至少保留链接目标、注音、脚注锚点和不可删除的非文本节点。

### 验收标准

- 含强调、超链接、ruby 和脚注的 fixture 导出后结构仍有效。
- 未翻译段落的 HTML 不发生无关变化。
- 导出 EPUB 通过 EPUBCheck 或等价结构校验。

## 10. R2-BUG-008：取消后重建已关闭客户端

### 位置

- `src/api/base_api.py:106-121`
- `src/core/translator.py:428-450`

### 现状

`cancel_requests()` 关闭客户端但不置空。`reset_cancel()` 只清除事件，`_get_client()` 只判断对象是否为空，不判断 `is_closed`。因此停止后再次翻译可能复用已关闭的 httpx 客户端。

### 修复要求

- 关闭客户端后立即置空，或在 `_get_client()` 中检查 `is_closed`。
- 客户端与心跳线程的读取、关闭和重建需要同步，避免并发重建。
- 增加“开始、停止、再次开始”的集成测试。

### 验收标准

- 连续执行 20 次开始/停止/开始不会出现 closed client 错误。
- 每次重建前旧客户端都已关闭。
- 取消后的下一次请求不等待心跳线程才能恢复。

## 11. R2-BUG-009：取消不能发送空批次覆盖结果

### 位置

- `src/core/translator.py:335-339`
- `src/core/translator.py:405-408`
- `src/core/translator.py:142-152`
- `src/ui/translation_controller.py:404-418`

### 现状

取消发生在批次内时，`_translate_batch()` 返回与批次等长的空字符串列表。上层仍按成功批次发送非流式进度回调，UI 把当前批次译文全部改为空并触发自动保存。

### 修复要求

- 使用取消异常或专用结果中断当前批次，不返回伪造的空译文。
- `CANCELLED` 路径不得发送最终成功批次回调。
- UI 合并结果时只覆盖已确认成功的索引。

### 验收标准

- 在流式输出中途停止后，已经确认的译文保留。
- 停止不会清除导入时已有或人工修改的译文。
- 取消后保存文件与停止前 UI 内容一致。

## 12. R2-BUG-010：检测响应中的缺失译文

### 位置

- `src/core/translator.py:358-400`
- `src/core/translator.py:168-182`

### 现状

模型漏掉行号或返回行数不足时，代码用空字符串补齐，但没有把对应原文非空的索引加入 `failed_indices`。只要 HTTP 响应非空，整个批次仍可能被判为 `SUCCEEDED`。

### 修复要求

- 对每个非空原文验证对应译文是否非空。
- 缺失、重复、越界和无法解析的行号都要形成失败索引。
- 无标记文本只能在映射可证明唯一时降级使用。

### 验收标准

- 20 行请求只返回 19 行时结果为 `PARTIAL`。
- 全部缺失时结果为 `FAILED`。
- 原文本身为空的行不计为失败。

## 13. R2-BUG-011：队列不得把 PARTIAL 标记为 completed

### 位置

- `src/core/concurrent_manager.py:249-277`

### 现状

队列只区分取消和完全失败。成功与部分成功都保存并设置 `completed`，之后可被“一键导出”选中。

### 修复要求

- 任务状态增加 `partial`，并保留失败索引和最后错误。
- `partial` 可保存成功内容，但不能进入普通完成导出集合。
- 提供继续失败行或明确确认导出不完整结果的入口。

### 验收标准

- 任一必需行失败时任务不显示“已完成”。
- 部分结果保存后仍能准确继续失败行。
- 默认一键导出不包含 partial 任务。

## 14. R2-BUG-012：关闭队列后禁止继续调度

### 位置

- `src/core/concurrent_manager.py:56-66`
- `src/core/concurrent_manager.py:198-210`
- `src/core/concurrent_manager.py:285-287`

### 现状

`close()` 只关闭当前引擎，没有关闭标志，也没有取消 pending 任务。运行线程离开时仍在 `finally` 中调用 `_start_next_pending()`，可能在应用退出过程中创建新引擎和新线程。

### 修复要求

- 增加受锁保护的 `_closed` 状态。
- `close()` 原子地禁止新任务、取消 pending、停止 running，并移除进度回调。
- `_start_next_pending()` 和 `start_task()` 首先检查关闭状态。

### 验收标准

- 关闭时存在一个 running 和多个 pending 任务，不会启动下一项。
- 关闭后调用 `start_all()` 或 `start_task()` 不创建线程。
- 关闭可重复调用且不会死锁。

## 15. R2-BUG-013：队列窗口必须拥有管理器生命周期

### 位置

- `src/ui/concurrent_window.py:31-44`
- `src/ui/main_window.py:327-328`
- `src/ui/main_window.py:379-385`

### 现状

队列窗口没有注册 `WM_DELETE_WINDOW` 清理管理器。主窗口每次打开都会创建新窗口并覆盖 `_concurrent_window` 引用，因此较早窗口的管理器无法在主窗口关闭时统一释放。

### 修复要求

- 队列窗口关闭时调用 `manager.close()`，取消刷新回调后再销毁窗口。
- 主窗口只允许一个队列窗口，或维护全部子窗口集合。
- 后台回调必须能识别窗口已销毁并停止投递。

### 验收标准

- 关闭队列窗口后没有任务继续访问网络。
- 连续打开和关闭 10 次不会增加后台线程。
- 主窗口退出能关闭所有曾创建的队列管理器。

## 16. R2-BUG-014：续翻只处理真正缺失的行

### 位置

- `src/ui/translation_controller.py:122-180`

### 现状

代码虽然找出了全部缺失索引，但只使用第一个缺口作为起点，然后翻译从该行到末尾的全部原文。缺口之后已经翻译或人工校对的行会被重新翻译并覆盖。

### 修复要求

- 构造缺失行列表及其原始索引，回调按索引写回。
- 不要用连续起始偏移代表非连续缺口集合。
- 续翻期间人工已有译文必须只读保留。

### 验收标准

- 第 2 行为空、第 3 行已有人工译文时，只请求和更新第 2 行。
- 多个非连续缺口均写回正确位置。
- 续翻请求数量与实际缺失行数一致。

## 17. R2-BUG-015：详情页编辑必须落盘

- 编辑完成任务后关闭窗口、重启应用，修改仍存在。
- 编辑后立即一键导出包含新译文。
- 模拟只读目录时不显示保存成功。

## 18. R2-BUG-016：图片输出使用唯一身份和真实媒体类型

### 位置

- `src/core/image_translator.py:247-271`
- `src/core/epub_processor.py:797-825`

### 现状

## 24. R2-BUG-022：原子写入使用唯一临时文件

### 位置

- `src/utils/file_handler.py:18-41`

### 现状

## 25. R2-BUG-023：心跳不得关闭活动流式客户端

### 位置

## 31. 必须新增的回归测试

### EPUB fixtures

- 字符串、对象和非线性 spine。
- 不同目录下同名章节和同名图片。
- 原文修改、章节增删、源文件替换。
- 含 `em`、`strong`、`a`、`ruby`、脚注和 SVG 的章节。

### 翻译状态

- 取消发生在首 chunk、批次中间和批次完成边界。
- 20 行请求返回 19 行、重复行号、缺失行号和空响应。
- 队列 partial、保存失败、关闭时存在 pending。
- 非连续空行续翻和人工译文保护。
- 队列已有译文保护与空任务持久化。

### 密钥迁移

- 正常 keyring、Null/fail backend、写入异常和回读不一致。
- 旧 API 配置、旧预设和旧火山 Key 文件。
- 重启进程后验证密钥仍存在，磁盘和日志不含明文。

### 持久化和图片

- 详情页编辑后重启与导出。
- 并发原子写入。
- 图片检测 401、429、超时、部分失败和全部失败。
- 图片翻译第二次空结果、源图变化和同名图片。
- 长流式请求跨越多个心跳周期，心跳失败不影响活动请求。
- 图片连接测试和正式任务的客户端关闭。
- 后台任务期间关闭窗口，不产生迟到 Tk 回调错误。
