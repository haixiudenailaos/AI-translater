# 用户体验与功能优化路线图

## 1. 文档目的

本文档从最终用户完成翻译任务的全过程出发，整理当前项目值得实施的用户体验和功能优化方向，并给出优先级、目标行为与验收标准。

本路线图不把“用户体验”简单理解为换颜色、调整图标或增加动画。对于长文本和 EPUB 翻译工具，用户体验首先取决于以下能力：

- 已有译文不会被意外覆盖。
- 长任务可以暂停、恢复，并在应用重启后继续。
- 用户在发起任务前知道范围、模型、风险和大致成本。
- 失败能够定位到具体批次或行，并可只重试失败部分。
- 导出前能够确认译文完整、术语一致、EPUB 结构有效。
- 界面只在当前上下文中提供可执行的操作。

实施功能或性能改造前，还应结合以下文档：

- [Bug 修复指南](./BUG_FIX_GUIDE.md)
- [模块拆分与重构指南](./MODULE_REFACTORING_GUIDE.md)
- [性能优化指南](./PERFORMANCE_OPTIMIZATION_GUIDE.md)

## 2. 产品目标

建议将产品定位从“单次调用 API 的翻译界面”调整为“可恢复、可质检的文档翻译工作台”。

核心工作流应保持清晰：

1. 导入文件或恢复最近项目。
2. 确认目标语言、模型、术语库和翻译范围。
3. 查看预计行数、耗时和费用。
4. 执行翻译，并持续保存检查点。
5. 处理失败行和质检问题。
6. 预览并导出结果。

## 3. 当前基础

项目已经具备继续演进的基础能力：

- TXT、EPUB 和剪贴板导入。
- 原文与译文按行对照展示。
- 流式进度更新。
- 停止、续翻和选中行翻译。
- EPUB 图片识别和插图翻译入口。
- 术语库管理。
- 顺序任务队列与任务详情。
- API 连接测试、模型和提示词配置。
- 译文、对照文件和 EPUB 导出。

后续重点不是继续堆叠入口，而是让这些能力共享一致的任务状态、保存策略、错误模型和交互规则。

## 5. P0：可靠性与数据安全

### 5.1 UXF-001：保护已有译文

#### 当前问题

主界面的“开始翻译”会先清空整个译文列。用户此前导入的译文、已经完成的批次和手工修改内容都会进入覆盖风险。

#### 建议行为

- 主按钮改为“翻译未完成行”。
- 只提交原文非空且译文为空的行。
- 将“重新翻译全部”放入次级菜单。
- 重新翻译全部前显示影响范围，并要求确认。
- 执行覆盖前创建项目级检查点，允许撤销到翻译前版本。
- 手工编辑过的行增加 `manually_edited` 标记，默认不被自动任务覆盖。

#### 验收标准

- 点击主翻译按钮不会修改任何已有非空译文。
- 用户明确选择“重新翻译全部”后才允许覆盖。
- 覆盖操作至少保留一个可恢复检查点。
- 中途停止后，已经完成和手工修改的行保持不变。

### 5.2 UXF-002：续翻必须精确到缺失行

#### 当前问题

续翻逻辑从第一个空译文位置截取到文档末尾，后续即使存在已完成译文，也会再次提交并写回。队列任务同样会拼接全部原文，没有真正跳过已有译文。

#### 建议行为

- 统一使用“待翻译行索引列表”，不再使用“从某行开始到末尾”的范围模型。
- 将待翻译行和 API 返回行通过稳定索引映射。
- 续翻、查漏、选中行翻译和队列翻译共享同一套稀疏行翻译接口。
- 只在返回非空且索引匹配时写回目标行。
- 失败行保持原值，并记录错误原因和尝试次数。

#### 验收标准

- 文档中间存在空行、后方存在已译行时，续翻不会修改后方译文。
- EPUB 中已有译文的行不会被队列任务重新请求。
- API 费用与实际待翻译行数一致，不包含已完成行。
- 重试失败行不会触发成功行的重复翻译。

### 5.3 UXF-003：统一保存语义

#### 当前问题

设置窗口提供“启用自动保存”，但主窗口保存调度没有读取该配置。保存失败还存在被静默忽略的路径，用户无法判断当前内容是否已经落盘。

#### 建议行为

- 自动保存设置直接控制保存调度。
- 将状态分为“已保存”“有未保存更改”“正在保存”“保存失败”。
- 在状态栏展示最后保存时间和保存目标。
- 保存失败不得吞掉异常，应保留未保存状态并提供“重试保存”。
- 自动保存使用原子替换，并为项目数据保留最近若干检查点。
- 关闭应用或切换项目时，如有未保存内容应明确提示。

#### 验收标准

- 关闭自动保存后，编辑和翻译进度不会自动写入目标文件。
- 开启自动保存后，批次完成和手工编辑都能触发受控保存。
- 磁盘只读、空间不足或路径失效时，界面显示可操作的错误。
- 用户始终能够判断当前内容是否已保存。

### 5.4 UXF-004：项目与队列持久化

#### 当前问题

队列管理器和任务状态保存在内存中。关闭队列窗口、退出应用或进程异常结束后，用户无法恢复任务列表、运行位置和错误信息。队列中的 TXT 任务通常只在完成时保存结果，长任务的中间成果保护不足。

#### 建议行为

为每个翻译项目持久化以下信息：

- 项目 ID、源文件路径、文件指纹和映射目录。
- 原文、译文、手工编辑标记和失败行。
- 当前状态、完成进度、最近批次和重试次数。
- 模型、目标语言、提示词版本和术语库快照。
- 图片翻译状态和导出记录。
- 创建时间、最后打开时间和最后保存时间。

队列窗口只负责展示共享任务服务，不应每次打开都创建一套新的独立任务状态。

#### 验收标准

- 应用重启后可以看到之前未完成的任务。
- 用户可以从最后一个已提交检查点继续，而不是从头开始。
- 关闭队列窗口不会丢失或隐藏后台任务。
- 源文件发生变化时提示用户重新导入或创建新项目。

### 5.5 UXF-005：明确任务终态

#### 当前问题

部分批次成功时，主流程能够识别“部分完成”，但队列流程可能仍将任务标记为“已完成”。导出入口只依据完成状态判断，存在输出残缺结果的风险。

#### 建议状态

- `pending`：等待开始。
- `running`：正在执行。
- `paused`：用户暂停，可恢复。
- `partial`：有成功结果，也有失败或缺失行。
- `completed`：全部必需内容成功且质检通过。
- `cancelled`：用户取消。
- `error`：任务无法继续，需要用户处理。

#### 验收标准

- 存在失败行时任务不能显示为“已完成”。
- 部分完成任务可以导出草稿，但必须明确标注缺失数量并二次确认。
- “一键导出”默认只处理真正完成的任务。
- 状态、进度、失败数量和可用操作保持一致。

### 5.6 UXF-006：安全存储 API 凭据

#### 当前问题

API Key 和包含 API Key 的预设直接写入 JSON 文件。界面中的掩码只能避免屏幕旁观，不能保护磁盘上的密钥。

#### 建议行为

- 使用系统凭据库保存密钥，Python 侧可通过 `keyring` 接入。
- 普通配置和预设只保存凭据引用，不保存明文 Key。
- 提供“记住密钥”开关；关闭时仅保存在当前进程内存。
- 日志、错误信息和诊断导出统一脱敏。
- 迁移旧配置时读取旧 Key、写入凭据库并安全移除明文字段。

#### 验收标准

- 新生成的配置和预设文件不包含完整 API Key。
- 日志与异常信息不包含密钥、Authorization 头或完整请求体。
- 凭据迁移失败时不删除旧数据，并给出明确处理提示。

## 6. P1：核心功能闭环

### 6.1 UXF-007：译前预检

开始翻译前提供简洁的任务摘要：

- 文件名、文件类型和目标语言。
- 总行数、已有译文数、待翻译数和手工编辑数。
- 当前提供商、模型和翻译策略。
- 预计输入/输出 token、费用区间和耗时区间。
- 术语数量、图片数量和需要图片翻译的数量。
- 超长行、空内容、疑似编码错误和 EPUB 解析异常。
- 本次操作是补译、选中行翻译还是重新翻译全部。

普通补译可以在主界面内显示摘要；高成本、覆盖性或批量任务再使用确认对话框，避免所有操作都被弹窗打断。

### 6.2 UXF-008：译后质检中心

当前“翻译查漏”主要检查空译文。建议扩展为可筛选的问题中心，至少覆盖：

- 原文非空但译文为空。
- 译文仍与原文高度相似，可能未翻译。
- 返回内容残留 `[LINE_XXX]` 等内部标记。
- 行数、数字、专名和标点异常。
- 术语库要求未命中或同一术语译法不一致。
- 译文异常短、异常长或连续重复。
- EPUB 目录、章节、链接、图片引用和封面完整性。
- 图片翻译失败或仍存在待处理图片。

质检面板应支持：

- 只显示问题行。
- 按问题类型和严重程度筛选。
- 跳转到上一个或下一个问题。
- 忽略单个问题并记录原因。
- 重新翻译选中问题。
- 导出质检报告。

### 6.3 UXF-009：可操作的错误

错误信息需要回答“发生了什么、影响了多少内容、接下来能做什么”。建议统一错误分类：

- API Key 无效或权限不足。
- 余额或额度不足。
- 请求限流。
- 网络超时或连接中断。
- 模型不可用。
- API 返回格式不符合行映射协议。
- 本地文件无权限、路径失效或磁盘空间不足。
- EPUB 解析或导出失败。

任务详情应显示失败批次、失败行数、最后错误、尝试次数和建议操作，并提供“重试失败行”“更换模型后重试”“打开日志目录”等入口。

重试策略应采用指数退避和随机抖动，并区分可重试错误与不可重试错误。鉴权失败不应自动重试 5 次，限流和临时网络错误可以重试。

### 6.4 UXF-010：重定义翻译模式

当前“逐行模式”和“快速模式”共用相同批处理流程，主要差别只是批次间延迟，名称无法准确描述实际行为。

建议调整为：

| 模式 | 面向用户的含义 | 推荐策略 |
| --- | --- | --- |
| 稳定 | 优先保证对齐和失败隔离 | 小批次、严格校验、低并发 |
| 均衡 | 默认选择 | 中等批次、正常校验、受控并发 |
| 高速 | 优先缩短总耗时 | 大批次、允许更高并发、明确风险 |
| 自定义 | 高级用户调参 | 开放批次、并发、超时和重试策略 |

模式切换后应直接展示其影响，不使用用户无法验证的模糊名称。

### 6.5 UXF-011：完善队列管理

建议为队列补充：

- 拖动或按钮调整任务顺序。
- 展示待翻译行数、完成数、失败数和预计费用。
- 每个任务选择模型、目标语言和术语库。
- 仅重试失败任务或失败行。
- 可配置并发数，并根据提供商限流自动约束。
- 关闭窗口后继续运行，并在主窗口显示全局任务状态。
- 完成后可选系统通知。
- 批量导出时列出成功与失败文件及具体原因。

“全部取消”“移除任务”等破坏性操作需要确认；“移除已完成”可以提供短时间撤销。

### 6.6 UXF-012：缓存与用量统计

项目已有缓存模块，但主翻译路径尚未形成明确集成。建议在保证缓存键完整的前提下接入：

- 缓存键至少包含原文、目标语言、模型、提示词版本和术语库版本。
- 手工要求重新翻译时允许绕过缓存。
- 展示本次请求数、重试数、缓存命中数和估算费用。
- 按项目记录累计用量，但不记录未脱敏的敏感原文到诊断日志。
- 提供清理当前项目缓存和清理全部缓存的明确入口。

## 7. P2：界面与操作效率

### 7.1 UXF-013：重构主界面层级

当前主界面同时展示导入、剪贴板、模式、队列、术语库、设置、开始、续翻、停止、查漏、图片翻译和多个导出按钮。建议按任务频率重组。

#### 推荐布局

- 顶部项目栏：当前文件、目标语言、模型、保存状态和设置。
- 左侧或顶部次级导航：当前项目、任务队列、术语库。
- 中央工作区：原文/译文对照表和问题筛选。
- 底部固定任务栏：翻译未完成行、暂停/继续、进度、失败数量。
- “导出”菜单：译文、对照文件、EPUB 和质检报告。
- EPUB 包含图片时才显示图片翻译状态和入口。

空白状态不应只显示“就绪”，而应提供“导入文件”“粘贴文本”和“打开最近项目”三个明确入口。

### 7.2 上下文驱动的控件状态

- 未导入内容时禁用翻译、保存和质检。
- 当前不是 EPUB 时隐藏或禁用 EPUB 导出和图片翻译。
- API 未配置时，主操作显示“配置 API”而不是点击后弹出警告。
- 翻译运行时禁用会破坏当前任务的数据操作。
- 有失败行时主操作优先显示“重试失败行”。
- 全部完成后主操作变为“运行质检”或“导出”。

按钮状态、状态文字和实际业务能力必须来自同一个任务状态模型，避免界面与后台状态不一致。

### 7.3 UXF-014：提高校对效率

建议增加以下编辑能力：

- 搜索原文或译文，支持区分大小写和正则表达式。
- 筛选全部、未翻译、失败、手工修改和质检问题。
- 上一个/下一个问题导航。
- 多行编辑器，而不是仅依赖表格内单行输入框。
- 显示当前行前后文。
- 撤销、重做和恢复到自动译文。
- 多选行批量清空、标记完成或重新翻译。
- 复制原文、复制译文和交换查看宽度。
- 长文本自动换行或展开查看，避免依赖水平滚动条。

术语库建议补充：

- 全局术语库和项目术语库。
- 大小写敏感、全词匹配和启用状态。
- 导入冲突预览，可选择覆盖、跳过或保留两者。
- 从当前项目提取高频专名并生成候选术语。
- 展示术语在当前项目中的命中次数和未遵循次数。

### 7.4 减少模态打断

成功添加术语、保存完成、普通批次完成等低风险反馈优先使用状态栏或非模态通知。以下情况再使用模态对话框：

- 即将覆盖已有译文。
- 删除或取消不可恢复的数据。
- 高成本批量操作。
- 应用无法继续的错误。
- 导出残缺结果。

通知应短暂显示但可在活动记录中回看，避免用户处理长任务时连续关闭消息框。

### 7.5 UXF-015：桌面可用性与可访问性

- 增加标准快捷键：`Ctrl+O`、`Ctrl+S`、`Ctrl+F`、`Ctrl+Z`、`Ctrl+Y`。
- 为“翻译选中行”等右键功能提供键盘可达入口。
- 在菜单中展示快捷键，解决 F5/F6 不可发现的问题。
- 支持 Windows 高 DPI 缩放和可调字号。
- 不将“微软雅黑”作为唯一字体，提供系统字体回退。
- 焦点顺序与视觉顺序一致，并显示清晰的键盘焦点。
- 不只用颜色表达失败、完成和选中状态。
- 使用稳定、统一的图标资源，避免依赖不同系统渲染不一致的 Emoji。
- 窗口缩小时保证主操作和状态不被工具栏挤出。

## 8. 推荐实施阶段

### 阶段一：建立信任

目标：消除覆盖、丢失和错误完成状态。

- 完成 UXF-001 至 UXF-006。
- 增加针对开始、续翻、暂停、关闭和恢复的自动化测试。
- 主界面展示可靠的保存状态。
- 队列和主翻译流程统一使用结构化任务结果。

阶段一完成前，不建议投入较多精力重做视觉主题。

### 阶段二：形成质量闭环

目标：让用户知道翻译是否完整、失败在哪里、费用是否合理。

- 完成译前预检和用量估算。
- 上线质检中心和失败行重试。
- 重定义翻译模式。
- 完善队列配置、重试和导出报告。

### 阶段三：提升高频操作效率

目标：减少点击、弹窗和人工查找成本。

- 重构主界面信息层级。
- 增加筛选、搜索、上下文编辑和撤销重做。
- 改造术语库冲突处理和项目术语能力。
- 完成键盘、高 DPI 和字体适配。

## 9. 验收指标

建议在实施前记录基线，改造后持续观察：

### 9.1 可靠性指标

- 已有译文被非预期覆盖的次数应为 0。
- 应用异常退出后，最后检查点恢复成功率应达到 100%。
- 标记为“已完成”的任务必须没有必需内容缺失。
- 保存失败必须全部对用户可见，不允许静默失败。

### 9.2 效率指标

- 从启动应用到发起首次有效翻译的操作步骤。
- 从失败发生到成功重试失败行的操作步骤。
- 校对人员定位下一个问题所需时间。
- 重复翻译请求占全部 API 请求的比例。
- 缓存命中节省的请求数和估算费用。

### 9.3 体验指标

- 单次完整任务中阻断式弹窗数量。
- 用户能否在不打开日志的情况下理解失败原因。
- 用户能否在主界面判断当前文件、模型、进度和保存状态。
- 800x600、1000x700 和高 DPI 缩放下是否仍可访问主要操作。

## 10. 关键回归场景

至少为以下场景建立自动化或可重复的手工验收脚本：

1. 导入包含已有译文的 TXT，执行补译，确认已有译文不变。
2. 文档中间有空译文、后方有手工译文，执行续翻，确认只更新空行。
3. 翻译完成若干批次后停止、退出、重启并恢复。
4. API 返回部分成功，任务显示部分完成并只允许带提示导出草稿。
5. API 返回 401、429、超时和格式错误，界面给出不同建议。
6. 关闭自动保存后编辑译文，确认磁盘文件未自动变化。
7. 自动保存失败后恢复磁盘权限，使用“重试保存”成功落盘。
8. EPUB 包含已有文字和图片翻译结果，重新打开项目后状态完整恢复。
9. 队列中包含成功、部分成功和失败任务，一键导出只导出合格任务。
10. 使用纯键盘完成导入、搜索、选择问题行、保存和导出。

## 11. 暂不优先的工作

在 P0 问题解决前，以下工作收益较低，不建议优先投入：

- 大规模更换配色或视觉主题。
- 为所有操作增加动画。
- 在任务状态仍不可靠时增加更多导出格式。
- 在没有限流和费用保护时盲目提高并发数。
- 在没有完整缓存键和失效策略时直接启用全局缓存。
- 将更多高级设置直接堆放到主窗口。

正确的实施顺序应是：先保证数据与状态可信，再补齐质量和恢复能力，最后优化视觉层级与操作效率。
